# 検証記録

確認日: 2026-09-23。この記録は開発時に利用した1台のWindows 11 x64ホストと別のWindowsクライアントの結果です。任意のPCで導入済み・検証済みという意味ではありません。

## 実機で確認した構成

ホストGPUはNVIDIA GeForce RTX 4070、Sunshineは2026.914.233613、Virtual Display Driverは25.7.23を使用しました。通常時は物理3画面、配信時は仮想1画面、クライアントの要求解像度2880×1920で確認しています。音声には既存のSteam Streaming Speakersを使用しました。

## 実機で確認したこと

| 対象 | 結果 |
| --- | --- |
| 配信 | SunshineとMoonlightのペアリング、Desktop表示、マウス・キーボード操作 |
| 自動消灯 | 新規Desktop起動時に物理画面が無効になり、仮想画面のみ有効 |
| 入力の区別 | Moonlight操作では消灯維持、登録した物理マウス・キーボードで復帰 |
| 画面復元 | 最新構成では画面ID・位置・サイズ・Hzが元の物理3画面と一致し、仮想画面は無効。回転もアプリ内部で検証 |
| 切断 | 物理復帰後に標準ユーザーからSunshineサービスを再起動してMoonlightを切断 |
| 音声 | 仮想出力からのキャプチャをログで確認し、操作端末だけの再生を利用者が確認 |
| 解像度 | 2880×1920と1920×1080への切り替え、未対応サイズの拒否 |
| キャプチャ | 切り替え前後にGPUのDesktop Duplicationフレーム取得 |
| 異常終了 | 常駐プロセス単独の強制終了後にGuardianが画面を復元 |
| 任意設定 | 自動消灯を無効にした場合の、物理画面を維持した仮想画面配信 |
| 自動起動の設定 | StartupショートカットとSunshineサービスの自動起動設定 |

利用者は最終構成の消灯・物理復帰・切断・音声が問題なく動作したと回答しています。機械ログによる確認と利用者による確認を合わせた受け入れ結果です。端末ID・IP・生ログ・画面バックアップは公開しません。

追加の「配信中だけ仮想画面を有効にする」変更後も、利用者が接続・切断後の画面復元を確認しています。Sunshineログで2880×1920の仮想画面だけをHEVC配信していることを確認しました。変更後のCLI復帰は約1.33秒、Guardianによるクラッシュ復旧は約2.33秒で、いずれも物理3画面に戻りました。これはこのホストでの1回の計測値です。

## キーボードの追加診断

当初は「半角／全角」を`0xC0`から`0xF4`へ置き換えた直後の切り替えを利用者が確認しました。しかし、その後にIMEが連続して切り替わる症状の報告があり、この方式の受け入れ結果は撤回しました。

短時間のSunshine診断ログでは、Caps Lock／英数の単押し3回に対して`0x14`の押下が1回、続くShift付き操作で初めて解放を受信しました。「半角／全角」についても記録区間には押下だけがありました。対象版Sunshineのソースでは、解放を受信していないキーをリピートし、その都度置換先を送る処理を確認しました。これらは報告された連続切り替えと整合します。診断ログレベルはInfoに戻しています。

ホストの2つの`0xF4`向け割り当てを解除し、サービスの再起動後に設定の読み戻しを確認しました。物理3画面のみ有効、復旧待ちなしの通常状態へ戻ったことも確認しています。ただし利用者から、解除後も「半角／全角」の位置の記号が連続入力されるとの報告があり、置換の解除だけでは症状を止められませんでした。

その後、暫定対処として`key_repeat_delay = 0`を適用し、Sunshineを再起動しました。全リモートキーの長押しリピートが使えなくなる制限を利用者へ説明しています。設定の読み戻しとサービスの起動を確認しましたが、再接続後に連続入力が止まったかは利用者の確認待ちです。クライアント側の解放欠落とCaps Lock単押しの対応は未解決です。

回帰テストでは、2つの割り当てを同時に解除すること、他の独自割り当て・コメント・改行の保持、繰り返し実行、曖昧な設定の拒否を検証しました。リピート停止は独立した設定とし、無効化・標準値への復帰・独自遅延値への復帰を検証しました。`Build.ps1 -Publish`でセットアップ・構文58件、コア・アプリ境界58件、言語設定補助8件、コンソールなしCLI2件が成功し、ビルドは警告0・エラー0でした。言語設定補助の模擬テストは、実機でCaps Lockが使える証拠としては扱いません。

## 自動検証

公開前の変更前ベースラインはReleaseビルド成功（警告0、エラー0）、コアテスト39/39、コンソールなしCLIの出力リダイレクトあり／なし2件成功でした。公開前レビューで追加したテストと最終結果は[公開前レビュー](publication-review.md)に記載します。

共通の再実行コマンドは`powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Build.ps1 -Publish`です。GitHub Actionsも同じコマンドを使用します。これらの自動検証ではドライバを導入せず、画面構成を変更しません。
